# GreywireAndroid - Claude Context

## What this project is

A native mobile app for **Greywire Studio**, Cherry Blossom Development's guitar-effects brand (the Linework pedals). It is one of two sibling apps:

| Project | Platform | Repo |
|---------|----------|------|
| **GreywireAndroid** | Android (Kotlin, Jetpack Compose, Retrofit) | https://github.com/Cherry-Blossom-Development/GreywireAndroid |
| **GreywireiPhone** | iOS (Swift, SwiftUI, XcodeGen) | https://github.com/Cherry-Blossom-Development/GreywireiPhone |

Both apps should offer the same features; build a feature in one, then match it in the other.

### How it relates to the other projects

- **GreywireStudio** (`../GreywireStudio`): the hardware side, meaning the pedal designs (KiCad, LTspice). The apps are the mobile companion to these products.
- **GreywireStudio-Website** (`../GreywireStudio-Website`): the Greywire web front end. **The app's look comes from this site** (see "Visual design" below).
- **Breakroom** (`../Breakroom`): the backend for these apps. They use the **same Express backend, MariaDB database and user accounts** as Prosaurus (`https://www.prosaurus.com/api`). **Any new backend endpoints or tables these apps need go into the Breakroom backend.** Don't create a separate backend. Greywire-specific routes live under `/api/greywire` (`backend/routes/greywire.js`).
- **Android** / **iPhone** (`../Android`, `../iPhone`): the Prosaurus mobile apps. **These are not the same apps.** The Greywire apps use the same tech stack and backend, and reuse patterns and code from them (auth, API client, environment switching, Socket.IO), but the interface and structure are very different. Some Prosaurus features will be carried over; many Greywire features won't exist in Prosaurus at all.

## Status

Foundation built 2026-11-09: login and a home screen.

- **Login**: works the same way as the Prosaurus app. `POST /api/auth/login`, the JWT goes into EncryptedSharedPreferences, and later calls send it as a Bearer header plus a `jwtToken` cookie. Refreshed tokens from the `X-New-Token` header are saved.
- **Home**: a header with the brand, a hero section, the user's Greywire membership (`GET /api/greywire/membership`: member or not, plus claimed pedals), and cards for Flashover and Switchyard with their illustrations (2026-11-23). The pedal text is static and copied from the website.
- **Legal** (2026-11-16, matching GreywireiPhone): Home has a "Terms and policies" card leading to Legal Documents, which shows the EULA's acceptance status (`GET /api/eula/status`) and the Privacy Policy. Both documents are in-app screens (`LegalDocuments.kt`) with the same text as the web versions at community.greywirestudio.com; if that text changes, update both apps. - **EULA accept step** (2026-11-16, both apps): every signed-in launch, and every login, goes through `EulaGate` before Home. If `GET /api/eula/status` says the EULA isn't accepted, the user sees the EULA with a pinned footer: "Accept These Terms" (`POST /api/eula/accept`, then Home) or "Decline and sign out". A 401 signs out; any other error lets the user through, as Prosaurus does. Acceptance isn't cached on the device, so it's checked on each launch.
- **Navigation** (2026-11-20): five bottom tabs, Home, Sessions, Chat, Friends and Profile, matching the web community's menu. The Sessions, Chat, Friends and Profile tabs are described below; Sign out is on Profile (moved there from Home's header). Login, the EULA step and sub-screens (Claim, Legal, EULA, Privacy) are full screen. Back from a tab goes to Home.
- **Claim by QR code** (2026-11-23, matching GreywireiPhone): the claim screen has "Scan QR code", using Google's code scanner (`play-services-code-scanner`; Play services shows the camera UI, so the app needs no camera permission). A scanned code fills in the serial and claims it straight away.
- **Guest accounts** (2026-11-23, both apps): `/api/auth/me`'s `isGuest`. Home's membership card says guests can't claim pedals or become members, and the claim screen shows the same instead of the form.
- **Paywall** (2026-11-23, both apps): `AuthResult.Error.requiresSubscription` is set on a 402. `PaywallScreen` (route `paywall?message=`) shows the backend's message, the plan from `GET /api/billing/plan`, the Pro benefits, and that subscribing is on the website until in-app purchase (roadmap 1.11). On Android, a session upload over the free-tier limit opens it (`showPaywall` in `NavGraph.kt`, 2026-11-24); on iOS it isn't triggered yet.
- **Friends** (2026-11-23, matching GreywireiPhone): the Friends tab has two sections, Friends (with online dots; remove, after confirming) and Requests (incoming with accept/decline, sent with cancel, after confirming), with a count badge for incoming requests and pull to refresh. Opening it marks requests seen. Uses `/api/friends`, `/api/friends/requests`, `/api/friends/sent` and the action endpoints. A third section, **Find** (2026-11-27, Android only so far), searches as you type (`GET /api/friends/find?q=`, at least 2 characters; it leaves out anyone you're already connected to) and Add sends a request (`POST /api/friends/request/:id`), moving the person to Sent.
- **Chat** (2026-11-23, matching GreywireiPhone): the Chat tab has Rooms (`/api/chat/rooms`, the Greywire community's rooms) and Messages (`/api/chat/dms`, with unread counts and the last message), with pull to refresh. A room opens inside the tab (Back returns to the list): its messages (`/api/chat/rooms/:id/messages`, oldest first, "Load earlier messages" with `before`), a text input and Send. Opening a room marks it read. REST only for now, so new messages from others appear when the room is reopened; images and videos show as a placeholder.
- **Sessions** (2026-11-23, matching GreywireiPhone): the Sessions tab has My Sessions (`/api/sessions`) and Band (`/api/sessions/band-members`, with the uploader), each with a count badge and pull to refresh. A session opens inside the tab: type, instrument and band, a player (Media3 ExoPlayer streaming `/api/sessions/:id/stream` through `RetrofitClient.mediaHttpClient`, which sends the token), the 1-10 rating picker (`POST /api/sessions/:id/rate`; tapping your current rating clears it) and the dates (the recording date is shown in UTC, since the backend sends it as UTC midnight). **Upload** (2026-11-24, Android only so far): "Upload a recording" on My Sessions opens `SessionUploadScreen` inside the tab: an audio file (copied to the cache; up to 100 MB, nginx's limit), name, Band practice or Solo take, band (`/api/bands`) or instrument (`/api/instruments`), and the recording date. It's one multipart `POST /api/sessions` through `RetrofitClient.sessionsUploadApiService` (5-minute timeouts, as the server transcodes before answering; no body logging). A 402 opens the paywall. **Delete**: your own sessions (opened from My Sessions) have "Delete session", after confirming (`DELETE /api/sessions/:id`). Recording, comments and sharing aren't built yet.
- **Profile** (2026-11-24 to 11-26, Android only so far): the Profile tab shows your profile as the web community's Profile page does on Greywire (`GET /api/profile`): photo (`/api/uploads/<photoPath>`, loaded with Coil) or initial, name, @handle, member since and friend count; About (the bio); the Musician Profile (music bio, "musician only", instruments, bands; Greywire only); Details (email, names); and Sign out. Bios are HTML from the web's rich-text editor, shown with `HtmlText` (`ProfileParts.kt`). Prosaurus's work history (work bio, skills, jobs) is left out, as on the web. **Editing** (2026-11-25): "Edit profile" (names and the About bio, `PUT /api/profile`, which also needs the hidden work bio sent back, nulls written out); "Edit music bio" (`PUT /api/profile/musician`, sending the musician-only setting back); the musician-only switch on the tab; tapping an instrument or band (or "Add") opens its form with Remove; "Add/Change photo" picks with Android's photo picker and uploads a JPEG shrunk to 1024px (`PhotoResize.kt`), or removes it. Bios are edited with `RichBioEditor` (`compose-rich-editor`), with the web's toolbar (bold, italic, strikethrough, lists, heading, undo, redo); an unchanged bio is saved back exactly as loaded. The tab keeps the last profile (`ProfileRepository.lastProfile`) so it doesn't jump to the top after an edit. **Other members' profiles** (2026-11-26): tapping anyone on the Friends tab (a friend, an incoming or a sent request) opens `UserProfileScreen` (route `user/{handle}`, `GET /api/profile/user/:handle`), read only, without About when they show only their Musician Profile. The web's Block and Flag buttons aren't there yet (`TODO.md`). **Settings** (2026-11-26): "Settings" on Profile opens `SettingsScreen` with the web's sections: notifications (`/api/user/notification-settings`, saved as each switch changes), the alternate email (set, which sends a confirmation email; resend, change, remove; and once confirmed, whether notices go there) and the account deletion request (an "I understand" box, then `POST /api/profile/deletion-request`; an administrator processes it). The backend sends some of these booleans as `0`/`1`; `LenientBooleanAdapter` reads both.
- **Tablet and landscape** (2026-11-23, matching GreywireiPhone): the tabs' content (Home, Sessions, Chat, Friends, Profile, an open room or session) is centered and capped at 632dp (`Modifier.readableWidth()`), the same as iOS's 632pt. Sub-screens (`GreywireSubScreen`) cap at 520dp, the login form at 420dp.
- If the saved token is rejected (401), the app signs out and goes back to Login.

**The feature plan is `ROADMAP.md`**: phases and steps, with the status of each step in Backend, Web, Android and iPhone. Update it whenever a step is done. **Smaller loose ends are tracked in `TODO.md`**, including sign up, forgot password, pedal claiming, push notifications, release signing and E2E tests. Keep it up to date as items are done or found.

## Visual design: match GreywireStudio-Website

The app should look like `../GreywireStudio-Website` (`css/site.css`). It's dark only, and Android 12 dynamic color is off.

- **Colors** (`ui/theme/Color.kt`) are the site's `:root` variables: bg `#141619`, surface `#1c1f23`, surface-2 `#24282d`, line `#33383e`, text `#e8e6e1`, muted `#9ba0a6`, copper `#d07a3e`, copper-soft `#e9a46f`, signal `#5fd38a`. If the site's palette changes, change these to match.
- **Fonts**: Space Grotesk for text and IBM Plex Mono for labels, both bundled in `res/font` under the OFL (license texts are in `licenses/`). There's no static SemiBold Space Grotesk, so 600 maps to Medium.
- **Components** (`GreywireComponents.kt`), with the site class each one mirrors: `GreywireHeader` (`.site-header`), `GreywireBrand` (`.brand`), `Eyebrow` (`.eyebrow`), `GreywireCard` (`.card`), `StatusPill` (`.status`), `GreywireButton` (`.button`), `GreywireGhostButton` (`.button.ghost`), plus `GreywireTopBar` (back arrow and title for sub-screens; no site equivalent), `GreywireSubScreen` (a full-screen sub-screen: top bar plus scrolling content capped at 520dp), `Modifier.readableWidth()` (the tabs' 632dp cap) and `GreywireBottomBar` with the `GreywireTab` enum (`GreywireBottomBar.kt`; the tabs match the web community's menu). Build new screens from these.
- **Pedal illustrations**: `res/drawable-nodpi/pedal_flashover.png` and `pedal_switchyard.png` are the site's `img/flashover.svg` and `img/switchyard.svg` rendered at 3x (600x900) with headless Chrome, since the SVGs use text, which vector drawables can't draw. If the site's SVGs change, render them again: `chrome --headless=new --default-background-color=00000000 --force-device-scale-factor=3 --window-size=200,300 --screenshot=<out>.png <file:///...svg>`.
- **Logo**: `res/drawable/ic_greywire_logo.xml` is a vector port of the site's `img/logo.svg`. The launcher icon is adaptive (the wire and spark on surface-2), with the full logo as the fallback below API 26.

## Environments

| Env file | BASE_URL | Use |
|----------|----------|-----|
| `local` | `http://10.0.2.2:3001/` | Local backend on the dev machine (emulator loopback) |
| `dev-test` | `https://test.dev.prosaurus.com/` | EC2 dev test backend |
| `production` | `https://www.prosaurus.com/` | Production |

```powershell
.\switch-env.ps1 local    # writes environments/active.properties (gitignored)
```

Debug builds read `BASE_URL` from `active.properties` (default `http://10.0.2.2:3001/`). Release builds always use production. Plain HTTP is allowed only to `10.0.2.2`, and only in debug builds (`app/src/debug/res/xml/network_security_config.xml`).

To test locally, start the Breakroom test backend on port 3001 (from `../Breakroom`: load `.env.test`, then `docker compose -f docker-compose.test.yml up -d backend-test`). Its seeded users are `testuser` / `TestPass123` and `testadmin` / `TestPass123`.

Note: the backend only recognizes the `X-Client-Platform` values `web`, `android` and `ios`, so Greywire traffic is currently counted as `android` in analytics, together with Prosaurus. To tell them apart, add a value such as `greywire-android` to `backend/utilities/platform.js`.

## Build & install

The versions match `../Android`: AGP 9.3.0, Kotlin 2.4.10, Compose BOM 2026.06.01, compileSdk/targetSdk 37, minSdk 24.

```bash
cd "C:/Users/dalla/Repo/GreywireAndroid"
./gradlew.bat assembleDebug --rerun-tasks
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`local.properties` (the SDK path) is gitignored, so copy it from `../Android` on a new machine. Release signing is used only when a `keystore.properties` exists; Greywire needs its own upload key before the first Play Store release (don't reuse Prosaurus's).
